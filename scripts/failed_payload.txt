## 这玩意儿到底有多坑？

说实话，我本来以为这事儿很简单。不就是改个 MSI 嘛，用 ORCA 打开，找到 Property 表，把 CustomerID 字段填上，保存，收工。

结果呢？翻车了整整三天。

我们团队在推一个 Win32 应用时，客户要求必须把他们的客户 ID 硬编码进 MSI 里，不能靠命令行传参——因为他们的 SCCM 部署脚本写得跟屎一样，没法处理复杂参数。我一开始也试过用 PSADT 封装，结果每次跑都报 fatal error，查了半天日志，发现是 MSI 本身的 CustomAction 顺序跟 PSADT 的 wrapper 冲突了。

好吧，那就直接用 ORCA 改原始 MSI。

## ORCA 到底怎么用？别信那些垃圾教程

网上搜出来的教程，十个有八个是教你改个 Property 值就完事了。但客户 ID 这东西，有时候藏在 Property 表里，有时候藏在 Registry 表里，甚至可能是个硬编码在 CustomAction 里的 DLL 参数。

我翻了微软官方的 Orca.exe 文档，说实话，写得跟天书一样。它就是个数据库表编辑器，你得知道自己在改什么。

### 第一步：打开 MSI 并找到目标

装好 ORCA 之后，右键点击 MSI 文件 -> "Edit with Orca"。别直接双击，那只会跑安装程序。

进去之后，左边那排表才是关键。别被吓到，你只需要关注这几个表：

| 表名 | 用途 | 常见坑 |
|------|------|--------|
| Property | 存储 MSI 全局属性 | 客户 ID 可能不叫 CustomerID，可能叫 LICENSEKEY 或 ACC_ID |
| Registry | 注册表写入规则 | 有些软件靠这个在安装时写注册表 |
| CustomAction | 自定义动作 | 这里可能藏了个 DLL 调用，参数是硬编码的 |
| InstallExecuteSequence | 执行顺序 | 改错了可能导致安装顺序崩掉 |

我这次要找的客户 ID，藏在了 **Property 表**里，键名叫 `CUSTOMER_KEY`。但问题是——这个键的值是空的，得靠外部传入。

### 第二步：直接改 Property 值

选中 Property 表，找到 `CUSTOMER_KEY` 那一行，把 Value 字段改成你的客户 ID，比如 `ABC-123-XYZ`。

**等等，别急着保存。**

如果你直接保存 MSI，下次再打开，这玩意儿就变成只读的了。而且更坑的是——如果你在 ORCA 里改了 MSI 并保存，ORCA 默认会**不保留嵌入的流文件**（比如 CAB 包里的压缩文件），导致 MSI 损坏。

所以你必须先做这个操作：
1. 点击 Tools -> Options
2. 选 Database 标签
3. 勾上 **"Copy Embedded Streams During Save As"**
4. 点 OK

这一步不做，你改完的 MSI 直接废掉。

### 第三步：用 Transform 而不是直接改 MSI

这里有个更好的做法——**生成一个 MST 转换文件**，而不是直接改 MSI。

为什么？因为直接改 MSI 会破坏数字签名，而且如果你要部署到多个客户，每个客户的 ID 不同，你得维护 N 个 MSI 版本，太蠢了。

操作流程：
1. 打开原始 MSI
2. 点击 Transform -> New Transform
3. 在 Property 表里把 `CUSTOMER_KEY` 改成目标值
4. 点击 Transform -> Generate Transform
5. 保存为 `.mst` 文件

部署的时候，用 `msiexec /i "your.msi" TRANSFORMS="your.mst"` 就行了。

### 第四步：如果客户 ID 藏在 Registry 里

有些傻逼软件厂商，把客户 ID 写死在注册表里。这时候你得在 ORCA 里操作 **Registry 表**。

我遇到过一个案例：某款监控软件安装完后，需要在 `HKLM\SOFTWARE\Vendor\Product` 下写一个 `CustomerID` 字符串值。

操作：
1. 在 Registry 表里新增一行
2. Root 填 `-1`（代表 HKLM）
3. Key 填 `Software\Vendor\Product`
4. Name 填 `CustomerID`
5. Value 填你的客户 ID
6. Component_ 字段要关联到一个已有的 Component，不然这个注册表项不会被写入

这个关联 Component 的步骤，是大多数人翻车的地方。你必须去 **Component 表** 里找个现成的组件，或者自己新建一个，然后在 **FeatureComponents 表** 里把它关联到一个 Feature。

## 真实踩坑记录

我们团队在推一个叫 "SecureAgent" 的软件时，遇到了更恶心的坑。它的客户 ID 不是存在 Property 表，而是通过一个 CustomAction 调用的 DLL 传入的。

我打开 ORCA 看了一下 CustomAction 表，发现 Source 字段指向了一个 DLL，Target 字段里写的是 `SetCustomerID`。这玩意儿根本没法在 ORCA 里直接改参数——你得反编译那个 DLL。

最后怎么解决的？我们写了个 PowerShell 脚本，在 MSI 安装完成后，直接修改注册表。虽然不优雅，但能用。

## FAQ

### 如何用 ORCA 编辑 MSI 文件？

打开 ORCA，File -> Open 选择 MSI，在左侧表列表中找到目标表（通常是 Property），修改 Value 字段，然后保存。记得先勾选 "Copy Embedded Streams During Save As"。

### 如何用 ORCA 打开 MSI？

安装 ORCA 后，右键 MSI 文件选择 "Edit with Orca"，或者先打开 ORCA 再 File -> Open。

### 如何用 ORCA 创建 MST 文件？

打开 MSI -> Transform -> New Transform -> 修改需要的表 -> Transform -> Generate Transform -> 保存为 .mst 文件。

### 如何用 ORCA 创建转换文件？

同上。MST 文件本质就是记录你对 MSI 做的所有修改的差量文件。

## 总结

| 场景 | 推荐做法 | 风险等级 |
|------|----------|----------|
| 客户 ID 在 Property 表 | 直接改 Value 或生成 MST | 低 |
| 客户 ID 需写入注册表 | 在 Registry 表新增条目并关联 Component | 中 |
| 客户 ID 藏在 CustomAction DLL 里 | 别用 ORCA 硬改，考虑 post-install 脚本 | 高 |
| 需要部署到多个客户 | 必须用 MST 转换文件 | 低 |
| MSI 有数字签名 | 直接改 MSI 会破坏签名，用 MST | 中 |

最后说一句：ORCA 是个好工具，但也是个危险工具。改之前一定备份原始 MSI，不然你哭都来不及。

## The Pain Point

Last month I spent three days fighting an MSI that refused to accept a customer ID via command-line arguments. The SCCM team's deployment scripts were—how do I put this gently—a dumpster fire. They couldn't handle complex parameters, so the request came down: "Just hardcode the customer ID into the MSI."

I tried PSADT first. Wrapper kept throwing fatal errors. Turns out the MSI's CustomAction sequence was conflicting with the wrapper. Classic.

So I went straight to the source: ORCA.

## What ORCA Actually Is (And Isn't)

Orca.exe is Microsoft's database table editor for Windows Installer packages. It's not a friendly GUI tool. It's a raw table editor. You need to know what you're doing.

Most tutorials online are garbage. They show you how to change a Property value and call it a day. But customer IDs can hide anywhere—Property table, Registry table, or buried inside a CustomAction DLL.

### Step 1: Open the MSI and Find Your Target

Install ORCA, right-click the MSI → "Edit with Orca". Don't double-click it—that runs the installer.

The left panel shows all the database tables. You only care about these:

| Table | Purpose | Common Gotcha |
|-------|---------|---------------|
| Property | Stores MSI global properties | Customer ID might not be called CustomerID—could be LICENSEKEY or ACC_ID |
| Registry | Registry write rules | Some apps write customer ID here during install |
| CustomAction | Custom actions | Could contain a DLL call with hardcoded params |
| InstallExecuteSequence | Execution order | Mess this up and your install breaks |

In my case, the customer ID was in the **Property** table, key named `CUSTOMER_KEY`. Value was empty—meant to be passed externally.

### Step 2: Edit the Property Value

Select the Property table, find `CUSTOMER_KEY`, change Value to `ABC-123-XYZ`.

**Don't save yet.**

If you save directly, ORCA by default **does not copy embedded streams** (like CAB files). Your MSI will be corrupted.

Do this first:
1. Tools → Options
2. Database tab
3. Check **"Copy Embedded Streams During Save As"**
4. OK

Skip this step and your modified MSI is trash.

### Step 3: Use Transforms Instead of Direct Editing

Here's the pro move: **generate an MST transform file** instead of modifying the MSI directly.

Why? Direct editing breaks digital signatures. Plus if you have multiple customers with different IDs, you'd need N versions of the MSI. That's stupid.

Workflow:
1. Open the original MSI
2. Transform → New Transform
3. Modify the Property table
4. Transform → Generate Transform
5. Save as `.mst`

Deploy with: `msiexec /i "your.msi" TRANSFORMS="your.mst"`

### Step 4: If the Customer ID Lives in the Registry

Some vendors hardcode customer IDs into registry keys during installation. I had one case where a monitoring agent needed `HKLM\SOFTWARE\Vendor\Product\CustomerID`.

In ORCA:
1. Add a new row to the Registry table
2. Root = `-1` (HKLM)
3. Key = `Software\Vendor\Product`
4. Name = `CustomerID`
5. Value = your customer ID
6. Component_ field must reference an existing Component

Step 6 is where everyone fails. You need to find a Component in the **Component table**, or create one, then link it in **FeatureComponents table** to a Feature. Otherwise the registry entry never gets written.

## Real-World Horror Story

We were deploying "SecureAgent" (name changed to protect the guilty). The customer ID wasn't in Property or Registry. It was passed to a CustomAction that called a DLL.

I opened CustomAction table. Source pointed to a DLL. Target was `SetCustomerID`. No way to change the parameter in ORCA—you'd need to decompile the DLL.

Solution? A PowerShell script that runs post-install to write the registry key directly. Ugly, but it works.

## FAQ

### How to edit an MSI file using ORCA?

Open ORCA, File → Open, select the MSI. Find the target table (usually Property), modify the Value field, save. Always enable "Copy Embedded Streams During Save As" first.

### How to open an MSI with ORCA?

Right-click the MSI in Windows Explorer → "Edit with Orca", or open ORCA first then File → Open.

### How to create an MST file for an MSI using ORCA?

Open MSI → Transform → New Transform → make changes → Transform → Generate Transform → save as .mst.

### How to use ORCA to create a transform?

Same as above. An MST is a delta file recording all changes made to the original MSI.

## Summary Table

| Scenario | Recommended Approach | Risk Level |
|----------|---------------------|------------|
| Customer ID in Property table | Direct edit or MST transform | Low |
| Customer ID needs registry write | Add Registry entry + link Component | Medium |
| Customer ID in CustomAction DLL | Don't use ORCA—use post-install script | High |
| Multiple customer deployments | Must use MST transform | Low |
| Signed MSI | Direct edit breaks signature—use MST | Medium |

Bottom line: ORCA is powerful but dangerous. Always back up the original MSI before touching it. I learned that the hard way.
