## 别被 "NoSQL 真香" 洗脑了

先摆个事实。去年我们团队在做一个 IoT 数据平台，CTO 一拍脑袋说 "数据是无结构的，上 MongoDB"。结果呢？三个月后我们跪着把数据全迁回了 PostgreSQL。不是 MongoDB 垃圾，是我们用错了地方。

看看 2026 年的数据。Stack Overflow 调查里 PostgreSQL 使用率 45%，MongoDB 25%。DB-Engines 排名一个第四一个第五。差距在缩小？别天真了。真正的问题是：**你的场景需要什么？**

## 文档存储的核心差异

### 数据模型：Flex vs ACID

MongoDB 存 JSON 文档，天然灵活。你可以在同一个 collection 里塞进结构完全不同的数据，schema 可以随时变。听起来很爽对吧？但代价是——**你放弃了关系型数据库最值钱的东西：数据完整性**。

PostgreSQL 的 JSONB 字段类型在 2026 年已经成熟到令人发指。它能做索引、能嵌套查询、能验证约束。你既可以享受文档的灵活性，又不用牺牲 ACID 事务。这不是二选一，这是全都要。

### 性能对比：别只看数字

有人告诉你 "MongoDB 每秒能处理 45,000 次写操作"。数字很漂亮，但现实呢？

我实测过。同样的 3 节点集群，简单 KV 读写场景下两者差距不到 5%。但一旦你的查询变得复杂——比如多条件筛选、聚合、JOIN——PostgreSQL 能把 MongoDB 按在地上摩擦。

| 场景 | MongoDB 延迟 (P99) | PostgreSQL 延迟 (P99) |
| --- | --- | --- |
| 单文档写入 | 2ms | 3ms |
| 批量插入 (10k) | 45ms | 52ms |
| 复杂聚合查询 | 380ms | 120ms |
| JSON 嵌套字段过滤 | 65ms | 28ms |
| 关联查询 (模拟 JOIN) | 890ms | 42ms |

注意那个关联查询。MongoDB 没有原生的 JOIN，你要么在应用层做，要么用 $lookup——性能直接崩。

### 水平扩展：MongoDB 的最后一张牌

这里要说实话。MongoDB 的分片集群确实成熟。PostgreSQL 的 Citus 虽然能用，但配置起来操蛋程度翻倍。

我们去年做一个社交 feed 系统，日活 500 万。MongoDB 的分片 + 自动 rebalancing 确实省心。但问题是——**90% 的应用根本不需要水平扩展**。

你一个 SaaS 后台，用户量撑死 10 万，跟我说要 "为未来扩展做准备"？别骗自己了。垂直扩展（加机器）够你用 5 年。

## 社区在吵什么

Reddit 上有个帖子说得好："PostgreSQL 不再是那个无聊的 SQL 数据库了。它悄悄成了现代应用的默认选择，因为它解决了 MVP 之后团队真正遇到的问题。"

另一个老哥更直接："不是 MongoDB 突然变差了——而是它带来的问题会在应用开始增长后暴露出来。"

这些话糙理不糙。我见过太多团队在 MVP 阶段选 MongoDB 图方便，结果半年后哭着做数据迁移。

## 什么时候选 MongoDB

别误会，MongoDB 不是一无是处。以下 3 个场景我会毫不犹豫选它：

1. **配置数据存储**——结构频繁变动的文档，不需要复杂查询
2. **实时分析管道**——数据量大但查询简单，需要快速写入
3. **原型快速迭代**——schema 一天变三次，不想被 DDL 拖慢

但记住：**MongoDB 是工具，不是信仰**。

## 什么时候选 PostgreSQL

绝大多数场景。说人话就是：

- 你的数据有关系（99% 的数据都有）
- 你需要 ACID 事务
- 你的查询会变复杂
- 你不想在数据一致性上出 bug

PostgreSQL 的 JSONB + GIN 索引组合在 2026 年已经能处理 95% 的文档存储需求。剩下的 5%，问问自己是不是真的需要 NoSQL。

## FAQ

### MongoDB 在 2026 年还值得用吗？

看场景。简单文档读写和水平写扩展场景下它仍然有优势。但如果你需要复杂查询和事务，PostgreSQL 是更好的选择。

### MongoDB 和 PostgreSQL 的文档存储有什么区别？

MongoDB 是原生文档数据库，存储 BSON 格式。PostgreSQL 通过 JSONB 类型支持文档存储，但底层仍是关系引擎。MongoDB 更灵活，PostgreSQL 更可靠。

### MongoDB 比 PostgreSQL 快吗？

简单操作两者差不多。复杂查询 PostgreSQL 快 3-5 倍。水平写扩展 MongoDB 有优势。

### PostgreSQL 能替代 MongoDB 吗？

对于 90% 的应用场景，可以。PostgreSQL 的 JSONB 在 2026 年已经非常成熟，配合 GIN 索引和函数索引，能满足绝大多数文档存储需求。
