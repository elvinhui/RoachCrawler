## 引子：当curl不在的时候

上周我们有个生产容器翻车了。镜像里没装curl、wget、甚至没有Python。运维大哥急得满头包："我连个健康检查都做不了！"

别急。Bash本身就藏着一把瑞士军刀——`/dev/tcp`。

这玩意儿不是新东西，Plan 9的遗产。Bash这老家伙一直在偷偷模仿Plan 9的`/net`接口。你猜怎么着？你完全可以用它手写HTTP请求。

## 基础操作：三行代码搞定GET请求

先来个最简单的：

```bash
exec 3<>/dev/tcp/example.com/80
echo -e "GET / HTTP/1.1\r\nHost: example.com\r\nConnection: close\r\n\r\n" >&3
cat <&3
```

看到了吧？`exec 3<>`打开了一个双向文件描述符，连到example.com的80端口。然后我们手动拼了个HTTP/1.1的GET请求，把响应读回来。

就这么简单。没有curl，没有wget，没有Python，纯Bash。

## 进阶：搞个能用的函数

裸写太累了。封装一下：

```bash
http_get() {
    local host=$1 path=${2:-/} port=${3:-80}
    exec 3<>/dev/tcp/$host/$port
    echo -e "GET $path HTTP/1.1\r\nHost: $host\r\nConnection: close\r\n\r\n" >&3
    cat <&3
    exec 3>&-
}
```

用法：`http_get example.com /api/health`

## 实战：写个健康检查脚本

这是我在Kubernetes initContainer里用过的东西：

```bash
#!/bin/bash
check_service() {
    local host=$1 port=$2
    exec 3<>/dev/tcp/$host/$port 2>/dev/null || return 1
    echo -e "GET /health HTTP/1.1\r\nHost: $host\r\nConnection: close\r\n\r\n" >&3
    local response=$(head -1 <&3)
    exec 3>&-
    [[ "$response" == *"200"* ]]
}

# 等MySQL就绪
for i in {1..30}; do
    if check_service mysql 3306; then
        echo "MySQL is ready"
        break
    fi
    sleep 2
done
```

比用curl省了至少20MB的镜像体积。真香。

## 但是——有坑

别高兴太早。`/dev/tcp`有几个大坑：

1. **只支持HTTP**。HTTPS就别想了。TLS握手你没法在Bash里搞。

2. **Bash编译时可选**。不是所有系统都支持。检查方法：
   ```bash
   [ -r /dev/tcp ] && echo "支持" || echo "不支持"
   ```

3. **性能拉胯**。每个请求都要建立新连接，没法复用。压测就别想了。

4. **Chunked编码翻车**。有些服务器返回chunked transfer encoding，你的`cat`会卡住。解决方法：
   ```bash
   cat <&3 | head -c $(grep -o 'Content-Length: [0-9]*' | cut -d' ' -f2)
   ```

## 对比表：curl vs /dev/tcp

| 特性 | curl | /dev/tcp |
|------|------|----------|
| HTTPS | ✅ 原生支持 | ❌ 不支持 |
| HTTP/2 | ✅ 支持 | ❌ 只能HTTP/1.1 |
| 连接池 | ✅ 支持复用 | ❌ 每次新连接 |
| 镜像体积 | ~20MB | 0（内置Bash） |
| 性能 | 高 | 低 |
| 脚本友好 | 需要安装 | 开箱即用 |
| 错误处理 | 详细 | 简陋 |
| 调试功能 | -v、--trace | 手动echo |

## 什么时候用？

- Docker镜像里没装curl，你又不想加（为了省体积）
- 嵌入式系统，空间寸土寸金
- 临时调试，手边没有工具
- 快速测试端口是否开放

## 什么时候别用？

- HTTPS请求（老实装curl或wget）
- 生产环境的监控脚本（用专业的健康检查）
- 需要处理复杂响应的场景

## FAQ

**Q: /dev/tcp支持HTTPS吗？**
A: 不支持。`/dev/tcp`只处理TCP层，TLS握手需要额外逻辑，Bash搞不定。

**Q: 所有Linux发行版都支持吗？**
A: 不一定。需要Bash编译时启用`--enable-net-redirections`。大多数主流发行版是开的，但Alpine Linux默认用ash，不支持。

**Q: 性能怎么样？**
A: 很一般。每个请求建立新TCP连接，没有HTTP keep-alive。适合低频检查，不适合高并发。

**Q: 怎么读取响应头？**
A: 用`read -u 3 line`逐行读，遇到空行就是头尾。

**Q: 能不能发POST请求？**
A: 可以，手动拼HTTP请求就行。但注意Content-Length要算对。
