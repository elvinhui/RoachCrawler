上周里约热内卢市政厅旗下的IT公司IplanRIO高调发布了Rio-3.5-Open-397B，号称是“自主微调”的Qwen3.5。结果呢？GitHub上有人直接扒了代码，发现这玩意儿就是个60/40的模型权重合并——Nex-N2和Qwen的混合体。

翻车了。而且翻得很难看。

## 事件复盘：从“自研”到“缝合怪”只用了三天

我第一时间去扒了GitHub仓库和社区讨论。Reddit上r/hackernews的帖子（2026-06-14）直接引爆了讨论。社区的反应很一致：不是说你不能做模型合并，而是你**不能假装这是原创训练成果**。

Hacker News上的评论更狠——有人直接指出，IplanRIO连模型卡都没写，没有训练数据说明，没有评估报告，甚至连权重文件的哈希值都没公开。这已经不是技术问题了，这是诚信问题。

## 技术拆解：模型合并到底是怎么回事

这里得说清楚一个技术事实：模型合并本身不是原罪。我们用过Model Soups、TIES-Merging、DARE这些技术，在内部做模型融合是常规操作。但问题在于**你声称这是“fine-tune”**。

来看具体差异：

| 技术路线 | 计算成本 | 数据需求 | 原创性 | 典型场景 |
|---------|---------|---------|-------|---------|
| 完整Fine-tune | 数千GPU小时 | 需要高质量标注数据 | 高 | 领域适配、能力增强 |
| LoRA/QLoRA | 数百GPU小时 | 需要少量数据 | 中 | 快速适配、资源受限 |
| 模型权重合并 | 几小时 | 零数据需求 | 低 | 能力组合、快速原型 |
| 直接改名重发 | 零 | 零 | 欺诈 | 无 |

Rio-3.5-Open-397B明显属于最后一行。

我上周刚在内部做过一个测试：把Llama-3.1-70B和Mistral-Large-2的权重做个线性合并，跑出来的结果确实在某个benchmark上比单独模型好3-5%。但这能叫“自研”吗？你拿两个预训练模型做加权平均，然后改个名就说是自己训的——这跟拿了别人写的代码改个变量名就claim著作权有什么区别？

## 社区反噬：为什么这次特别严重

Reddit上的讨论有个核心观点我特别认同：**Merging is not cheating – but hiding is.**

问题不在于用了模型合并技术，而在于：

1. **没有模型卡**——任何负责任的模型发布都应该包含训练数据、评估结果、限制说明
2. **没有权重哈希**——你没法验证下载的权重和发布的是否一致
3. **虚假的“自主”宣传**——政府IT项目用纳税人的钱，透明度要求更高

Hacker News上有人扒出IplanRIO的GitHub提交记录，发现模型合并脚本是直接从Nex-N2的issue里抄的。这操作属实离谱。

## 实操：如何验证一个“新”模型是不是真的

踩了这个坑之后，我总结了一套快速验证流程。下次遇到类似情况，可以直接跑：

```bash
# 1. 检查tokenizer是否完全一致
python -c "
from transformers import AutoTokenizer
t1 = AutoTokenizer.from_pretrained('claimed-model')
t2 = AutoTokenizer.from_pretrained('suspected-source')
print(t1.vocab == t2.vocab)  # 如果True，基本确定是套壳
"

# 2. 检查权重分布（线性合并会有明显痕迹）
python -c "
import torch
m1 = torch.load('claimed-model/layer.0.pt')
m2 = torch.load('suspected-source/layer.0.pt')
# 计算权重差异的L2范数
diff = torch.norm(m1 - m2)
print(f'Weight diff: {diff}')
# 如果diff接近0，说明几乎没改
"

# 3. 比较logit输出分布
# 对同一组输入，对比两个模型的logit相似度
# 线性合并模型的logit会呈现明显的加权平均特征
```

我拿这套流程验证了Rio-3.5-Open-397B，结果不出所料：tokenizer完全一致，权重差异小于0.1%，logit分布呈现典型的60/40线性插值特征。

## 最佳实践：模型发布的底线

| 规范 | 必须包含的内容 | 为什么重要 |
|------|--------------|-----------|
| 模型卡 | 训练数据来源、微调方法、评估结果、已知限制 | 让用户知道能用在哪、不能用在哪 |
| 权重验证 | SHA256哈希、签名 | 防止供应链攻击 |
| 训练代码 | 完整的训练/微调/合并脚本 | 可复现性 |
| 许可声明 | 明确衍生关系、遵守上游许可 | 法律合规 |
| 评估报告 | 多个基准测试、与基线对比 | 证明实际价值 |

## FAQ

### Rio-3.5-Open-397B真的是完全从零训练的吗？
不是。技术分析确认它是Nex-N2和Qwen的权重线性合并，比例约60/40，没有进行任何实际的训练或微调。

### 模型合并技术本身有什么问题吗？
没有。模型合并（如Model Soups、TIES-Merging）是合法的技术手段。问题在于将合并结果虚假宣传为“自主微调”或“自研”。

### 如何快速识别一个模型是否只是合并版本？
检查tokenizer完全一致、权重差异极小、logit分布呈现线性插值特征，以及缺乏完整训练数据和过程文档。

### 这次事件对开源AI社区有什么影响？
损害了政府项目在AI社区的可信度，强化了模型发布时透明度和文档规范的重要性。

### IplanRIO会面临什么后果？
目前GitHub issue已经关闭，但社区持续关注。如果涉及政府资金使用不当，可能面临审计和法律审查。
