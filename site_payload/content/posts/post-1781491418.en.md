## Fixing ERR-DISABLE Ports: The Real Deal

This is the one everyone hits first. I've watched junior engineers panic and start pulling cables.

### Symptoms
Port shows `err-disabled` in `show interface`:
```
GigabitEthernet1/0/24 is down, line protocol is down (err-disabled)
Reason: psecure-violation
```

### Root Cause
IOS-XE is paranoid by design. BPDU guard, port security, UDLD — they all kill the port the moment something looks wrong. Great for security, terrible when it false-positives.

### Step-by-Step Fix

1. **Diagnose first**
   ```
   show interfaces status err-disabled
   show errdisable detect
   ```

2. **Manual recovery (quick fix)**
   ```
   interface GigabitEthernet1/0/24
   shutdown
   no shutdown
   ```
   This gets you back online. It won't stop it from happening again.

3. **Auto-recovery (my go-to)**
   ```
   errdisable recovery cause all
   errdisable recovery interval 300
   ```
   Port comes back in 5 minutes automatically. Saves those 3 AM calls.

4. **If BPDU guard false positive**
   Check what's actually connected:
   ```
   show spanning-tree interface GigabitEthernet1/0/24 detail
   ```
   If it's a PC port with unnecessary BPDU guard:
   ```
   interface GigabitEthernet1/0/24
   no spanning-tree bpduguard enable
   ```

## Memory Leak: The MALLOCFAIL Nightmare

Hit this one last month. A Catalyst 9300 running 200+ days suddenly became unresponsive. SSH wouldn't connect. Logs were full of `%SYS-2-MALLOCFAIL`.

### Symptoms
```
%SYS-2-MALLOCFAIL: Memory allocation of 65536 bytes failed from 0x12345678, alignment 0
Pool: Processor Free: 4824 Cause: Memory fragmentation
```

### Root Cause
Here's the thing about IOS-XE memory management — it fragments badly over time. Even with free memory available, you can't get a contiguous block big enough. Common triggers:
- Bloated OSPF/BGP tables
- NetFlow caches not cleaning up
- SMU patches with memory leaks

### Step-by-Step Fix

1. **Emergency memory release**
   ```
   clear ip route *
   clear ip ospf process
   ```
   Warning: This causes routing flaps. Do it in maintenance window.

2. **Find the memory hog**
   ```
   show processes memory sorted
   show memory allocating-process top
   ```
   Found `linux_iosd-imand` eating 80% of memory on my box.

3. **Module reload (not full reboot)**
   IOS-XE lets you reload just the line card:
   ```
   hw-module subslot 1/0 reload
   ```
   Control plane stays up. Game changer.

4. **Version upgrade (permanent fix)**
   Checked BugID CSCwf83684 — fixed in 17.6.3+. Upgraded:
   ```
   request platform software package install file flash:cat9k_iosxe.17.09.01.SPA.bin
   ```

## OSPF Adjacency Flapping: The MTU Trap

Added a new switch. OSPF wouldn't form adjacency. Logs were screaming ADJCHG.

### Symptoms
```
%OSPF-5-ADJCHG: Process 1, Nbr 10.0.0.2 on GigabitEthernet1/0/1 from LOADING to FULL, Loading Done
%OSPF-5-ADJCHG: Process 1, Nbr 10.0.0.2 on GigabitEthernet1/0/1 from FULL to DOWN, Neighbor Down: Dead timer expired
```

### Root Cause
MTU mismatch. They had 1500, we had 9000. OSPF DD packets got fragmented. Neighbor kept bouncing.

### Step-by-Step Fix

1. **Check MTU on both ends**
   ```
   show interface GigabitEthernet1/0/1 | include MTU
   ```

2. **Align MTU or bypass**
   ```
   interface GigabitEthernet1/0/1
   mtu 1500
   ip ospf mtu-ignore
   ```
   `mtu-ignore` is a band-aid. Fix MTU properly in production.

## FAQ

### How do I recover an err-disabled port?
Fastest: `shutdown` then `no shutdown`. Better: configure auto-recovery:
```
errdisable recovery cause all
errdisable recovery interval 300
```
Port auto-recovers in 5 minutes. No manual intervention needed.

### What's the current stable IOS-XE version?
As of mid-2025, 17.9.x and 17.12.x are solid. 17.15.x is bleeding edge with known bugs. My picks:
- Production: 17.9.5 or 17.12.2
- Lab: Go ahead with 17.15.x

### What causes ERR-DISABLE?
| Trigger | Condition | Fix Direction |
|---------|-----------|---------------|
| psecure-violation | MAC conflict | Tune port-security |
| bpduguard | BPDU received | Verify port role |
| udld | Unidirectional link | Check optics/fiber |
| link-flap | Port bouncing | Inspect physical link |
| pppoe-ia | PPPoE auth fail | Review AAA config |

### What does confreg 0x2142 do?
Classic password recovery trick. Sets the config register to bypass startup-config on boot:
1. Reboot, hit Ctrl+Break for ROMmon
2. Type `confreg 0x2142`
3. Type `reset`
4. After boot: `copy startup-config running-config`
5. Change password, then `config-register 0x2102`
