## Stop Betting Everything on One Model

For the past six months, my team has been stuck on the same old problem: model selection. Every new project, we'd agonize over whether to burn cash on Claude Fable 5 or settle for GPT-5.5. Fable is stupidly expensive. GPT falls apart on certain reasoning tasks.

Then last month, I stumbled on a Reddit thread about OpenRouter's Fusion API. The title was a punch in the gut: "OpenRouter Fusion API Gets Near Fable 5 Results For Less." My first thought? Another hype piece. But the comments had real numbers. People were running benchmarks showing a panel of cheap models + a judge model matching Fable 5's performance.

I had to test this myself.

## What Fusion Actually Is

Here's the deal: Fusion isn't about calling one model. It's about defining a "model jury." You send one prompt, OpenRouter fans it out to multiple models simultaneously (GPT-5.5, DeepSeek V4 Pro, Gemini 3 Flash, whatever you pick), and a judge model synthesizes their outputs into a single answer.

Think of it as MoE-as-a-service. But unlike rolling your own Mixture-of-Experts pipeline, you don't have to build the routing, aggregation, or deduplication layers. OpenRouter handles all of that.

## The Pain Points and the Wins

### Pain: The docs are garbage

OpenRouter's official Fusion documentation is, frankly, low on signal. I spent 30 minutes figuring out how to define the panel in the request body. The key fields are `models` and `judge`, but the sample code doesn't show how to pass parameters to the judge.

I finally got it working after digging through a GitHub demo:

```python
import openai

client = openai.OpenAI(
    base_url="https://openrouter.ai/api/v1",
    api_key="sk-your-key-here"
)

response = client.chat.completions.create(
    model="openrouter/fusion",
    messages=[
        {"role": "user", "content": "Explain quantum entanglement in plain English"}
    ],
    extra_body={
        "fusion": {
            "models": [
                "openai/gpt-5.5",
                "anthropic/claude-opus-4.8",
                "google/gemini-3-flash"
            ],
            "judge": {
                "model": "anthropic/claude-opus-latest",
                "params": {
                    "temperature": 0.3,
                    "max_tokens": 2048
                }
            }
        }
    }
)

print(response.choices[0].message.content)
```

**Critical**: Set `model` to `"openrouter/fusion"` and define the panel inside `extra_body`. I initially passed a model list directly — got a 400 error. You're welcome.

### Pain: Pick the wrong judge and everything falls apart

I tried GPT-5.5 as the judge. It concatenated the responses from the panel and output a mess of redundant text. Switched to Claude Opus 4.8 — huge improvement. Someone on Reddit recommended `~anthropic/claude-opus-latest` (the tilde auto-tracks the latest version). Tested it. Solid.

### Win: The cost savings are real

We ran a head-to-head on an internal knowledge-base QA task:

| Configuration | Cost per Request | P99 Latency | Accuracy (Human Eval) |
|---|---|---|---|
| Claude Fable 5 solo | $0.085 | 4.2s | 89% |
| GPT-5.5 solo | $0.032 | 1.8s | 76% |
| Fusion (GPT-5.5 + DeepSeek V4 Pro + Gemini 3 Flash, Claude Opus judge) | $0.048 | 3.1s | 87% |

Two percentage points off Fable 5's accuracy, at nearly half the cost. For tasks that don't need 100% precision — content summaries, draft generation — this is a no-brainer.

## When Should You Use Fusion?

Here's my rule of thumb after a month of testing:

- **Complex reasoning** (legal analysis, code review, math proofs) → Use Fusion. Multiple models cross-validating each other cuts down hallucinations significantly.
- **Creative generation** (copywriting, storytelling, marketing) → Single model is fine. Fusion can actually flatten creative diversity.
- **Real-time chat** (chatbots, customer support) → Don't use Fusion. Three-second latency will kill user experience.
- **High-stakes accuracy** (medical diagnosis, financial compliance) → Stick with Fable 5. Fusion's 87% isn't enough.

## What the Community Is Saying

There's a heated Reddit thread right now: "OpenRouter Fusion API Makes Claude Fable 5 Look Outdated." The comments are split. Advocates say Fusion represents "model democratization" — no more vendor lock-in. Critics point out that latency is a killer in production.

My take? Fusion isn't a Fable 5 replacement. It's a complement. The smart play is building a dynamic routing layer — simple queries hit a single model, complex ones hit Fusion. We're building this internally. If it works out, I'll write a follow-up.

## FAQ

### What models does Fusion support?

Currently supports 400+ models from OpenAI, Anthropic, Google, DeepSeek, Kimi, and others. Full list on OpenRouter's site.

### Can I customize the judge model?

Yes. Specify any supported model in the `judge` parameter. Stick with strong reasoning models (Claude Opus, GPT-5.5) for the judge.

### What's the latency like?

Depends on your panel. A lightweight combo (GPT-5.5 + Gemini 3 Flash) runs 2-3 seconds. A heavy panel (with Claude Opus as judge) can hit 4-5 seconds. Slower than a single model, but faster than calling multiple models sequentially.

### How is billing calculated?

You're charged for the total output tokens across all participating models, including the judge. OpenRouter's site has a pricing calculator.
